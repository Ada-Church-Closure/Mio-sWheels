### 一、 核心数据结构（Redis 强相关）
- **跳表 (Skip List)：**
  - *考察点：* Redis ZSET 的底层实现。重点在于节点插入时随机层数的生成逻辑、以及多层级指针的更新与维护。
- **带有渐进式 Rehash 的哈希表 (Dict / Hash Table)：**
  - *考察点：* 模拟 Redis 的字典。除了基本的拉链法解决冲突，关键在于如何用两个哈希表（ht[0] 和 ht[1]）在读写操作中分摊数据迁移的开销，避免单次 Rehash 阻塞主线程。
- **LRU / LFU 缓存淘汰算法：**
  - *考察点：* 基础中的基础。LRU 通常要求 $O(1)$ 时间复杂度（哈希表 + 双向链表）。LFU 则需要更复杂的结构（如双哈希表 + 频次链表）来保证高效操作。
- **红黑树 (Red-Black Tree) / AVL 树：**
  - *考察点：* 极度考验编码基本功。红黑树重点在于插入和删除后的颜色调整和左旋/右旋逻辑（比如 Linux内核 `epoll` 底层就用到了红黑树）。如果觉得红黑树太复杂，通常写出结构清晰的 AVL 树也是可接受的。

### 二、 并发与多线程模型

- **无锁队列 (Lock-Free Queue) / 环形缓冲区 (Ring Buffer)：**
  - *考察点：* 高级并发。通常要求基于 CAS (Compare-And-Swap) 原语实现，需要深入理解内存屏障 (Memory Barrier) 以及经典的 ABA 问题如何规避。
- **多生产者多消费者模型 (MPMC) / SPSC：**
  - *考察点：* 线程同步的基础。利用 `mutex` 和 `condition_variable` 实现，核心在于正确处理**虚假唤醒 (Spurious Wakeup)** 以及队列空/满时的阻塞与唤醒逻辑。
- **简易线程池 (Thread Pool)：**
  - *考察点：* 任务队列的管理、工作线程 (Worker) 的生命周期控制，以及如何优雅地关闭线程池并清理未完成的任务。
- **读写锁 (Read-Write Lock)：**
  - *考察点：* 读多写少场景的优化。可能会要求基于互斥锁和条件变量手写一个读写锁，并处理“写饥饿”问题。

### 三、 内存管理与 I/O

- **内存池 (Memory Pool / Slab Allocator)：**
  - *考察点：* 避免频繁的系统调用和内存碎片。需要实现定长内存块的分配与回收，通常结合空闲链表 (Free List) 来做。
- **简易 Reactor 事件驱动模型 (基于 epoll)：**
  - *考察点：* Redis 的核心网络模型。手写一个简单的 Event Loop，注册 FD，处理 EPOLLIN/EPOLLOUT 事件，并分发给对应的回调函数。
- **时间轮 (Timer Wheel) 或 最小堆定时器：**
  - *考察点：* 处理海量网络超时或定时任务。最小堆容易实现，时间轮则更考验对底层心跳和 tick 推进的理解。

### 四、 字符串与内存操作（C 基础）

- **简单动态字符串 (SDS - Simple Dynamic String)：**

  - *考察点：* 模拟 Redis 的字符串。重点在于实现 $O(1)$ 获取长度、空间预分配（防止频繁重分配）、惰性空间释放，以及二进制安全。

- **安全的 `memmove` / `memcpy`：**

  - *考察点：* 面试高频。核心在于判断源地址和目标地址**是否存在内存重叠**。如果重叠，必须从后往前拷贝；如果不重叠，从前往后拷贝。

- **字符串转整数 (`atoi`)：**

  - ##### *考察点：* 极致的边界条件测试：空指针、前导空格、正负号、溢出处理（比较关键）、非法字符截断。
